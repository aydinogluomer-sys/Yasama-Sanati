# Awwwards SOTD Implementation Plan

## Project Context

This document converts the full Awwwards SOTD evaluation framework into an actionable `implementation.md` plan.

Primary target:

> Transform Yaşama Sanatı from a polished website into a memorable, art-directed, SOTD-level digital experience.

The goal is not only to improve technical quality. The goal is to create a site with a strong visual silhouette, memorable interaction language, editorial typography, cinematic section transitions, excellent usability, and production-grade technical craft.

---

## 0. Official Awwwards Scoring Model

Awwwards SOTD evaluation is weighted around four core dimensions:

| Category | Weight | Target Score |
|---|---:|---:|
| Design | 40% | 9.4 / 10 |
| Usability | 30% | 9.1 / 10 |
| Creativity | 20% | 9.3 / 10 |
| Content | 10% | 8.8 / 10 |

Weighted target:

```text
Design     9.4 × 0.40 = 3.76
Usability  9.1 × 0.30 = 2.73
Creativity 9.3 × 0.20 = 1.86
Content    8.8 × 0.10 = 0.88

Total = 9.23 / 10
```

Minimum internal target:

```text
Awwwards Honorable Mention baseline: 6.5+
SOTD internal target: 9.0+
Preferred internal target: 9.23+
```

## 1. Execution Principle

This is not a standard polish pass.

Previous polish passes improved invisible or technical layers such as:

- Responsive behavior
- Accessibility
- Reduced motion
- Dialog behavior
- Build stability
- Performance hygiene
- Minor UI consistency

This implementation must now target visible SOTD-level transformation.

Required transformation areas:

1. Hero silhouette
2. Editorial typography
3. Section-to-section transitions
4. Signature motion moments
5. Visual mass rhythm
6. Scroll storytelling
7. Interaction design
8. Footer as closing scene
9. Content as design material
10. Technical craft and performance

The site must no longer feel like a static layout with polish. It must feel like a sequence of intentionally directed scenes.

## 3. Phase 0 — Baseline Audit

### Objective

Create a brutally honest baseline score before implementing anything.

### Tasks

- Audit the current site against Awwwards categories.
- Identify whether the issue is design, usability, creativity, content, performance, accessibility, or technical craft.
- Separate invisible improvements from visible silhouette improvements.
- Identify which sections look too similar.
- Identify which interactions are generic.
- Identify where the site lacks a memorable scene.

### Required Output

Create or update:

```text
docs/awwwards-baseline-audit.md
```

The audit must include:

```text
Current Design Score:
Current Usability Score:
Current Creativity Score:
Current Content Score:
Weighted Current Score:

Biggest Weakness:
Biggest Opportunity:
Most SOTD-relevant section:
Most generic section:
Most urgent redesign target:
```

### Acceptance Criteria

- No implementation happens before the baseline audit.
- The audit must explicitly state why the current version is not yet SOTD-level.
- The audit must identify visible transformation opportunities.

## 5. Phase 2 — Art Direction

A SOTD-level site needs more than clean UI. It needs a memorable art direction system.

- Whitespace language

Use a restrained but cinematic visual system:

```text
Deep green / warm parchment / muted terracotta / soft bone / shadowed earth
```

Potential visual metaphors:

- Breath expanding space
- Inner alignment
- Energy channels
- Calm ritual
- Layered consciousness

### Do Not Use

- Random gradients
- Excessive glassmorphism
- Overly literal chakra colors

### Required Output

Create or update:

- The site has a clear atmosphere before the user reads the text.

## 7. Phase 4 — Hero Redesign

### Objective

Create a powerful first screen.

A weak hero severely reduces SOTD potential.

### Required Hero Qualities

- Large typography
- Net positioning
- Emotional tone
- Visual character
- Controlled motion entry
- Immediate brand atmosphere
- Non-template composition
- Strong first 5-second impression

### Required Hero Changes

- Radically change the visual silhouette.
- Increase typographic scale.
- Introduce one memorable hero moment.
- Use masked text reveal or cinematic line reveal.
- Add a strong visual mass contrast.
- Consider one full-bleed or near-full-bleed composition.
- Use motion as an entrance into the world, not as decoration.

### Possible Hero Moment Options

Choose one primary direction:

```text
Option A — Typographic Ritual
Large editorial headline emerges line-by-line through soft masks.
A handwritten accent appears as a final human gesture.

Option B — Breath Expansion
Hero image/shape slowly expands with scroll, as if the page is breathing.

Option C — Layered Awakening
Foreground typography, background image, and ambient texture move at different depths.

Option D — Quiet Cinematic Panel
The first viewport opens like a slow editorial title sequence.
```

### Acceptance Criteria

- The hero looks significantly different from the previous version.
- The hero can be used as a submission screenshot.
- The hero contains a recognizable signature moment.
- The hero does not sacrifice readability.

## 8. Phase 5 — Typography System

### Objective

Make typography a scene-building tool, not only text styling.

### Required Parameters

- Display font
- Body font
- Accent / handwriting font
- Type scale
- Line-height
- Letter-spacing
- Large heading system
- Editorial line breaks
- Responsive text behavior
- Text reveal
- Split text
- Handwriting accent
- Typographic hierarchy
- Numeric/details typography
- Link typography
- Button typography

### Required Typography Direction

Use:

- Large, calm, editorial display type
- Controlled line breaks
- High contrast between display and body text
- Handwriting only as a rare human accent
- Typographic tension through scale and spacing

Avoid:

- Generic wellness script fonts everywhere
- Too much handwriting
- Random font mixing
- Text that wraps unpredictably
- Hardcoded line breaks that break at intermediate widths

### Required Technical Work

Implement responsive-safe text splitting for animated text.

Manual JSX line breaks may remain only when:

- Breakpoints are fully tested
- Text does not overlap
- Intermediate tablet widths are safe
- The behavior is documented

Preferred solution:

```text
Dynamic text splitter for line / word / character reveal
```

### Acceptance Criteria

- Major headings feel editorial and intentional.
- No animated text breaks at tablet or narrow desktop widths.
- At least one large typographic scene exists outside the hero.

## 9. Phase 6 — Layout & Section Rhythm

### Objective

Make the page feel like a sequence of scenes instead of repeated stacked blocks.

### Required Layout Parameters

- Grid system
- Section rhythm
- Full-bleed areas
- Narrow column areas
- Asymmetry
- Overlap
- Layering
- Sticky sections
- Scroll-driven composition
- Visual mass balance
- Mobile layout reinterpretation
- Tablet breakpoints
- Hero fold control
- Footer composition
- CTA placement

### Required Rhythm Pattern

The page should alternate between:

```text
big / small
empty / dense
static / motion-led
light / dark
text-led / image-led
narrow column / full-bleed
slow / sharp
```

### Required Section Changes

- At least 3 sections must gain visibly different compositional behavior.
- At least 1 section must become full-bleed or near-full-bleed.
- At least 1 section must use asymmetry or overlap.
- At least 1 section must become a typographic scene.
- At least 1 section must use scroll-driven image or panel motion.

### Acceptance Criteria

- Sections no longer feel equally weighted.
- The user feels scene changes while scrolling.
- The page has visual rhythm and contrast.

## 10. Phase 7 — Section-to-Section Transitions

### Objective

Build a cinematic transition system.

Awwwards-level scroll experiences often treat sections as scenes. The transition between scenes matters as much as the section itself.

### Required Transition Types

Implement at least 3 of the following:

```text
Ambient background morphing
Panel overlap transition
Image zoom-in parallax
Typographic wipe
Soft screen wash
Sticky reveal
Clip-path expansion
Layered depth parallax
Footer closing transition
```

### Rules

- Do not use the same fade-up reveal everywhere.
- Every major section should have a transition character.
- Motion must be tied to scroll position where meaningful.
- Mobile transitions must be simplified.
- Reduced motion must be supported.

### Acceptance Criteria

- Scrolling feels like scene progression.
- Section transitions are visible but not distracting.
- At least one transition becomes a memorable site moment.

## 11. Phase 8 — Motion System

### Objective

Create one coherent motion language.

### Required Motion Parameters

- Motion principles
- Easing tokens
- Duration tokens
- Stagger tokens
- Scroll-linked motion
- Section transitions
- Text reveal
- Image reveal
- Card enter/exit
- Button hover
- Menu transition
- Page loading transition
- Reduced motion
- Mobile motion simplification
- Signature motion
- No over-animation

### Recommended Stack

Use:

```text
Motion
GSAP if needed for advanced timelines
Lenis for smooth scroll
```

Avoid:

```text
Anime.js
Barba.js
Random animation libraries
```

### Motion Timing Targets

```text
Button response: < 150ms
Micro interaction: 120–250ms
Standard reveal: 600–1200ms
Signature transition: 900–1600ms
Stagger: 50–90ms
```

### Acceptance Criteria

- Animations share the same rhythm.
- No animation feels random.
- Reduced motion path exists.
- Motion supports meaning, hierarchy, or flow.

## 12. Phase 9 — Signature Moment

### Objective

Create one memorable scene or interaction that people remember after leaving the site.

### Possible Signature Moments

- Hero typographic reveal
- Scroll-expanded image
- Cinematic section wipe
- Liquid / soft mask transition
- Large editorial headline scene
- Breath-like ambient background morph
- Cursor-reactive but subtle visual field
- Closing footer scene

### Required Decision

Choose only 1 primary signature moment and 1 secondary supporting moment.

Do not overload the site with many competing wow effects.

### Acceptance Criteria

- A reviewer can describe the site by one memorable interaction.
- The signature moment is aligned with the Yaşama Sanatı brand.
- It does not damage performance or usability.

## 13. Phase 10 — Interaction Design

### Objective

Make interactions feel bespoke and responsive.

### Required Interaction Parameters

- Hover states
- Active states
- Focus states
- Magnetic buttons
- Cursor effects
- Menu interaction
- Card interaction
- Scroll progress
- Drag/gesture if needed
- Form feedback
- Error feedback
- Microinteractions
- Touch target size
- Keyboard behavior
- Escape behavior
- Dialog behavior

### Required Fixes

#### Button SVG Stroke

Add non-scaling stroke behavior to SVG paths where needed:

```tsx
vectorEffect="non-scaling-stroke"
```

#### Button Hover Timing

Reduce delayed hover response.

Target:

```text
Delay: 0s–0.1s
Response: immediate
Duration: refined, not sluggish
```

#### Card Out-State

For scroll-driven card systems, add exit behavior:

- Cross-fade outgoing content
- Slide-out or mask-out previous card
- Avoid abrupt disappearance
- Maintain smooth text/image synchronization

### Acceptance Criteria

- Buttons feel immediate and premium.
- Cards transition in and out fluidly.
- Focus and keyboard states are functional.
- Interactions work on touch devices.

## 21. Yaşama Sanatı — Critical SOTD Tasks

The following tasks are mandatory for this project.

### 1. Radically redesign the hero silhouette

The hero must look visibly different from the previous version.

### 2. Add large editorial typography

The site needs at least one typographic scene outside the hero.

### 3. Use handwriting only as accent

Handwriting should be rare and meaningful, not decorative everywhere.

### 4. Build section transition system

Each major section should feel like a scene change.

### 5. Make each section feel different

Use visual mass, layout contrast, motion rhythm, and background shifts.

### 6. Turn scroll into storytelling

Scroll must feel like narrative progression, not simple page movement.

### 7. Fix ClipImageCard out-state / crossfade

Outgoing card content must not disappear abruptly.

### 8. Improve button hover response

CTA feedback must feel immediate.

### 9. Fix SVG stroke scaling

Use non-scaling strokes where SVG borders are stretched.

### 10. Implement responsive-safe text splitting

Text animations must not break at intermediate viewport widths.

### 11. Centralize motion tokens

All animation timings and easing values should follow one motion language.

### 12. Rebuild footer as a closing scene

Footer should feel like the final visual moment, not a utility block.
